# 故障辅助排查

## 先区分要解决的问题

- **解释资料**：“F30001是什么意思”“手册建议检查什么”。取得适用定义和出处即可，不为词义解释查询当前运行数据。
- **排查实际异常**：“这次为什么过流”“刚才反转与什么有关”。需将用户描述与实际事件、运行变化联系起来，输出可验证的候选原因。
- **决定下一步**：“先检查哪里”“还缺什么测量”。优先利用已有证据，给出能缩小原因范围的检查，不把所有分析重做一遍。

通用原理问题可解释原理，但不冒充本设备结论。对象或时间有关键歧义时先解决歧义；资料适用条件与代码检索流程遵循系统提示词，不在此另建规则。

## 围绕待验证原因取证

1. 说明已观察到的现象。用户叙述、采样事实和手册结论分别识别；先确认究竟是电流上升、代码事件、反转还是其他现象。
2. 只形成有数据或资料支持的候选原因，不凑固定数量。为每个候选明确“需要什么证据才能区分”，再决定查询哪些指标、时段或资料。
3. 对实际事件，比较异常前、发生时与后续的相关变化。只取与候选有关的观测；时序相关可支持进一步检查，不能独自证明因果。
4. 更新判断：已有支持证据是什么，有没有反向证据，关键观测是否缺失。没有观测不算已排除；多个原因仍无法区分时保留不确定性。
5. 给出下一项有区分力的检查，说明检查对象、目的及不同结果会怎样改变判断。先安排必要且可执行的核查；涉及停机、拆检或带电测量时交由人员按适用规程确认。

例如：负转速只说明观测到的方向，区分控制反向、机械带动与相序问题还需要对应的控制、联动或相序证据；判断三相不平衡必须取得相应三相观测。无法取得必要观测时停止升级根因断言，交付缺口和检查路径。

## 正式异常链路交付

用户要求异常分析、RCA或正式交付报告时，先用3至5行摘要说明本次能下的结论、不能下的结论和最高优先级动作；随后按以下六段顺序交付。摘要位于正文前，不计入六段。只做单项读数、代码释义或简单统计时，不强行套用此结构。

1. **异常事实**：只写成功查询结果或用户明确提供、可直接核验的事实。每条事实必须包含时间、对象、测点/参数、实测值、已配置阈值或基线、持续时间及证据编号；缺任一项都标记`【证据缺口：缺……】`，不得估算补齐。事实描述不写原因或影响。
2. **证据来源**：逐条列出证据编号、类型、设备/测点、时间戳或范围、关键内容/值、来源系统、数据/配置版本、采集状态及适用限制。证据编号必须原样引用本轮真实成功工具结果；不得伪造编号或引用历史轮次编号。结果未提供的来源字段标记“未提供/未知”。单位换算、时间对齐、基线比较等转换要说明规则及版本；版本未提供时如实注明。
3. **原因分析**：先说明需要解释的主效应，再按“直接原因（设备/部件机制）—条件因素（使机制发生或放大的条件）—系统性因素（维护策略、备件、设计裕量、采集配置等）”分层。每个原因分支分别标记`【证据支持】`、`【假设·待验证】`或`【已排除】`，并说明证据支持了什么事实、是否支持因果机制、反向证据及仍缺的验证；仅有相关性或先后关系不能写成根因。每条主要假设附可证伪的挑战句：“若该原因成立，应还能观察到……；需调取/检查……”。并列保留有依据且尚未排除的竞争假设；证据不足时明确写“系统性原因待评估”，不为了凑数编造原因。
4. **影响范围**：枚举有证据关联的设备/部件、冗余状态、工艺或支路、后果类别（安全、环境、质量、产能、寿命）、严重度判据和证据编号。对“继续运行24小时”的判断须注明工况、假设及依据；不能可靠量化时写明无法量化及需监测项。把潜在风险与已发生后果分开，不用无依据的“可能停机”代替分析。
5. **处置动作**：每项动作链接事实编号或原因分支编号，并写明动作内容、责任角色、期限、前置条件、安全要求、优先级及理由。只使用用户/记录提供的责任人和期限；未提供时写`【动作不完整：缺责任角色/期限/前置条件】`，可提出待确认项但不得伪装成已派工。优先级按P0（阻塞结论的数据问题）、P1（安全或关键工艺原因排查）、P2（口径与长期优化）标注。涉及停机、拆机、带电测量或参数修改时，明确要求按现场适用安全规程和授权执行。
6. **验证结果**：区分`【待验证】`与已完成结果。预先写明要消除的故障表现、验证方法、通过条件、数值阈值、观察时长/窗口、覆盖工况、验证责任角色及未通过后的转入动作。缺少通过条件或观察窗口时标记`【不可关闭】`；缺验证责任角色也须明确标记待确认。观察窗口未覆盖异常工况时标记`【验证不充分】`。仅有重启或单次复测正常不能关闭问题。

必要信息缺失时继续交付能核验的部分，并把缺口转成下一步取证或验证动作；不能用完整格式掩盖资料不足。支持“异常发生”与支持“原因成立”是不同证据等级，必须分别表述。事实编号可在本报告内按F1、F2顺序标记，但证据编号只能来自真实来源。避免固定展开无关字段，控制取证在能区分候选原因所需的最小范围内。

## 完成标准

资料解释要区分故障反应、故障确认方式和现场处置建议。手册的“应答”是故障确认字段，不写成“需立即应答”或“立即复位”等操作要求；只问故障含义时不必罗列该字段，需要解释时依据手册说明，不自行推断复位条件。归纳后的原因和检查项使用“可能原因”“建议检查项”等准确标题，只有逐字引用才称“手册原文”；保留各原因的适用工况，不能把不同驱动对象的条目拼成普遍适用的结论。

词义解释应有原码、具体含义、适用条件及可定位出处；实际排查应给出已确认现象、候选原因依据和下一步检查。仅罗列常见原因或贴出手册不算完成排查。需要图表或工单草稿时复用已经取得的证据，组合对应 Skill，不暗示已维修或已排除故障。

正式异常链路还须自检：事实缺项是否逐项披露；原因是否分层并区分机制证据与相关性；每条主要假设是否可被核查或证伪；竞争假设与系统性因素是否交代；影响是否有对象和判据；动作是否可追责；验证是否预设通过条件和覆盖工况。任一项不满足时修订或明确标记未完成，不得将未确认的诊断写成关闭结论。
