# 故障辅助排查

## 先区分要解决的问题

- **解释资料**：“F30001是什么意思”“手册建议检查什么”。取得适用定义和出处即可，不为词义解释查询当前运行数据。
- **排查实际异常**：“这次为什么过流”“刚才反转与什么有关”。需将用户描述与实际事件、运行变化联系起来，输出可验证的候选原因。
- **决定下一步**：“先检查哪里”“还缺什么测量”。优先利用已有证据，给出能缩小原因范围的检查，不把所有分析重做一遍。

通用原理问题可解释原理，但不冒充本设备结论。对象或时间有关键歧义时先解决歧义；资料适用条件与代码检索流程遵循系统提示词，不在此另建规则。

## 围绕待验证原因取证

1. 说明已观察到的现象。用户叙述、采样事实和手册结论分别识别；先确认究竟是电流上升、代码事件、反转还是其他现象。
2. 只形成有数据或资料支持的候选原因，不凑固定数量。为每个候选明确“需要什么证据才能区分”，再决定查询哪些指标、时段或资料。
3. 对实际事件，比较异常前、发生时与后续的相关变化。只取与候选有关的观测；时序相关可支持进一步检查，不能独自证明因果。
4. 更新判断：已有支持证据是什么，有没有反向证据，关键观测是否缺失。没有观测不算已排除；多个原因仍无法区分时保留不确定性。
5. 给出下一项有区分力的检查，说明检查对象、目的及不同结果会怎样改变判断。先安排必要且可执行的核查；涉及停机、拆检或带电测量时交由人员按适用规程确认。

例如：负转速只说明观测到的方向，区分控制反向、机械带动与相序问题还需要对应的控制、联动或相序证据；判断三相不平衡必须取得相应三相观测。无法取得必要观测时停止升级根因断言，交付缺口和检查路径。

## 完成标准

资料解释要区分故障反应、故障确认方式和现场处置建议。手册的“应答”是故障确认字段，不写成“需立即应答”或“立即复位”等操作要求；只问故障含义时不必罗列该字段，需要解释时依据手册说明，不自行推断复位条件。归纳后的原因和检查项使用“可能原因”“建议检查项”等准确标题，只有逐字引用才称“手册原文”；保留各原因的适用工况，不能把不同驱动对象的条目拼成普遍适用的结论。

词义解释应有原码、具体含义、适用条件及可定位出处；实际排查应给出已确认现象、候选原因依据和下一步检查。仅罗列常见原因或贴出手册不算完成排查。需要图表或工单草稿时复用已经取得的证据，组合对应 Skill，不暗示已维修或已排除故障。
