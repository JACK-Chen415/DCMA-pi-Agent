# 工单草稿整理

## 先确认用户要完成的交接

- 要整理草稿：把已有分析转成处理人员能理解和执行的任务说明。
- 要修改或复核草稿：针对指定内容检查证据、动作和缺项，不重做无关诊断。
- 要提交、派发或关闭：当前没有工单系统与操作工具，只能交付草稿及后续所需操作。不能改用后台监测任务冒充工单。

用户只问“怎么处理”时先给排查建议，不自动扩展到工单。当前草稿始终标注“工单草稿，尚未提交”。

## 从处理人员需要的信息组织内容

先回答三个问题：处理哪台设备的什么现象，已有何种证据，希望检查什么并如何复核。复用已有分析，用户提供的历史观察标明其来源，不自动查询当前数据替换历史现象。

草稿按实际信息组织，可采用以下紧凑结构，不为填满格式补造事实：

- **任务与对象**：设备、异常现象和观察时段，使处理人员能定位问题。
- **已知依据**：相关数值、原码及含义、资料出处，区分实测事实、用户描述与待验证判断。
- **建议检查**：检查对象、检查目的、需要记录的结果；原因未确认时安排核查，不直接写成已确定的维修方案。
- **复核条件**：用什么观测评价处理效果。已有阈值或规程才给通过标准；缺依据时列为待确认。
- **待补充项**：只列影响执行或审核的信息。负责人、期限、优先级等无依据时留待分配，不虚构工单号或审批记录。

缺关键设备身份时仍可整理其余内容，但应明确草稿尚不能直接执行；不因缺少非必填行政信息而停止整理。需要新增分析才能支撑建议时，先完成必要取证或把该项标成待核查。

## 完成标准

审核者应能看清任务对象、现象依据、下一步动作和复核缺口，且推测没有变成事实。文件、附件与报告只引用已有实际结果；草稿完成不等于正式建单，处理完成不等于验收关闭。涉及后续实际操作时保留人员确认要求，不以用户对草稿的认可冒充系统已提交。
