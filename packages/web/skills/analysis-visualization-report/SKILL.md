# 设备运行报告与可视化

## 交付目标与分支

让读者看清设备在报告期内的实际表现、值得关注的变化、证据能支持的判断及下一步行动。专业性来自分析有依据、结论有边界、建议能核查，不能用堆表格、术语或固定风险评级代替。

最终交付通过 `submit_analysis` 完成。模型选择本轮证据及结论类型，程序校验并生成正文，不另写一份自由报告绕过校验。简短分析用format=brief，完整报告用format=report；范围、数值、单位和手册名称页码均读取真实证据。先完成有价值的图表及用户要求的附件，再提交claims；程序按可核验结论生成对应章节，缺少证据的判断不生成。该工具只接受结构化结论选择，不接受标题、原因解释或任意数值；失败按具体原因最多修正一次，之后仅交付可核验部分并明确未完成完整分析。

- **简短运行分析**：“最近一周运行得怎么样”“本月运行情况”。复用下述范围、取证与判断规则，按 `device-operation-analysis` 用二至四个短段落交付主要表现、关键数据、代码事件及必要限制，按价值补表格或趋势图，不自动套正式标题和八节目录。
- **完整运行报告**：“生成该设备近一周的报告”“写一份运行周报”或明确要求详细展开。按下述完整正文结构编制，可包含有助于判断的图表；未明确要下载时，先在回答中交付正文。只有要求完整报告才使用第四节的完整目录，普通运行询问采用上一分支。
- **异常调查报告**：用户明确要解释某次异常、开展RCA或追查根因时，组合 `fault-investigation` 的正式异常链路；周报中发现代码事件不自动将整份周报改成RCA。
- **单独绘图**：按阅读目的选图，保留本Skill的图表规范，不强制生成整份报告。
- **整理已有报告**：复用原范围、回答和固定快照；只修改表达或导出时不重新分析、替换历史数据。

## 一、固定报告范围

优先采用当前所选设备、来源与用户指定时段，不为已明确的条件重复询问。设备无法唯一确定时先确认对象；缺厂家、型号或阈值不阻止编制有边界的运行报告。

“近一周”默认从本轮当前时刻向前连续7天，明确北京时间起止与生成时间；“上周”指上一个完整自然周，不能混用。查询过程中固定边界，资料、统计、事件、图表使用同一设备和范围。超过单窗口能力的范围按系统约束处理，部分时段结果不能冠以完整月报。

未限定主题的电机/变频器运行报告，默认覆盖：
- 热状态：电机温度 `motor_temp`、变频器温度 `inverter_temp`。
- 电气表现：实际电流 `current_actual`、直流母线电压 `dc_voltage`。
- 运动与负载表现：实际转速 `speed_actual`、实际转矩 `torque_actual`。

按主题和实际可用测点调整；缺字段如实说明，不为凑指标补造数值。只要温度周报时收敛到相关温度测点，不强行查询六项。与“设备基本信息”请求不同，报告已有明确时段时不附加最近一小时概况。

## 二、取得并核对最少证据

本轮已有相同范围的成功证据时直接复用；缺项才查询。标准运行周报通常从以下三项开始，不为每个章节重新取数：

1. `get_device_profile`：确认设备名称、可用单位及已有规则，只使用与报告相关的资料。
2. `summarize_metrics`：一次取得完整报告期所需指标、有效/缺失数、均值、极值、标准差、首末有效采样和趋势。显式选择测点；周趋势复用已有汇总间隔，报告中写明实际是每小时或每2小时等汇总。
3. `get_code_events`：同一窗口的故障、报警及各代码统计。全量汇总用于事件总数、代码累计观察跨度，分页明细只支持本页事件的特征。按 `eventDetailScope` 区分全窗口汇总与当前页；可使用各代码的累计/平均观察分钟数，原始毫秒仅留在证据中。明细不足全量时明确“共336次，本次查看其中50条”等实际范围；不能据此声称整周每次均持续2分钟、严格每30分钟一次。累计跨度除以次数只能说明平均观察跨度，不能证明每次相同；必要明细可在预算内补查，不无限翻页。

先检查证据能否支持报告：
- 请求范围、实际首末采样时间、总记录数、每个指标的有效数与缺失数、无数据时段、截断及失败项分别交代。
- 完整范围查询成功只代表查询覆盖了该范围，不代表设备连续采样、无断点或一直在线。按统计的 `analysisScope` 区分已查询与未检查项目；没有连续性证据时写“已查询完整时段，所查指标无缺值”，不写“完整采样”“数据覆盖完整”、时间完整率或“采集无中断”。此边界同样适用于摘要和结论。
- 基础覆盖核验使用统计自带信息；只有用户要求连续性质量分析并给出最大采样间隔时才补 `check_data_quality`。周原始数据超过工具上限时，披露未完成的连续性验证，不拿聚合点代替原始记录。
- 全窗口无数据时交付简短的“报告期无可用数据”说明，列范围、来源和未完成项，不生成空图或正常结论；部分缺失时继续报告可核验部分，指出受影响的结论。

## 三、分析应回答的问题

| 分析内容 | 必须说明的含义 | 需要守住的边界 |
| --- | --- | --- |
| 整体水平 | 各指标自己的均值、最小/最大值及波动程度 | 不直接比较温度、电流、转速等不同单位的标准差大小；没有明确统一比较尺度及相应计算时不排名“最平稳”“波动最大”，不为排名编造评分。标准差不单独证明安全、稳定或异常 |
| 时段变化 | 有证据的升降、峰谷所在汇总时段及变化前后表现 | 小时极值不能给出精确峰值时刻；首末差不代表全周持续趋势 |
| 指标关系 | 温度、电流、转速等是否在相同时段出现相关变化 | 相同窗口均值不足以证明同步变化，更不证明原因；未按报警区间对齐采样或统计时，不写“报警期间指标未偏离”“没有同步变化”或“无影响”。没有对应证据就省略，不为填章节臆造关联 |
| 故障与报警 | 已观察到的事件次数、主要原码及含义、相关时段和观察时长 | 采样点不是事件，事件跨度不是已确认停机时长；沿用工具的事件合并语义，不推断跨缺口持续故障 |
| 规则与对比 | 有明确规则时才判断对应条件；有可比基线时才解释差异 | 阈值缺失仍可描述数据；无规则不判健康，无基线不编造“环比改善” |

仅在用户要求比较或已有可用基线时补前一等长时段对比，使用同设备、同测点、同单位和相同统计口径；基准均值为0时不报告无定义的变化百分比。新增比较不挤占本期基本统计和事件核验，也不把工况差异解释成设备劣化。

有原码时按系统流程检索、保留原码和释义及适用条件；在结论旁仅用普通文字说明依据的实际手册名称及页码，不提供原文链接、接口地址，不输出内部引用编号和检索记录表。根据资料和实际现象提出检查项，不能照搬全部手册。预算不足导致释义或分析未完成时，指出具体缺项。

不从现有统计擅自生成运行时长、开机率、停机损失、耗电量、效率、MTBF/MTTR、健康评分、故障概率或剩余寿命；这些需要各自的状态规则、事件定义、积分计算或额外业务证据。

电流或转矩接近零只说明对应测点的观测值；缺少额定值、负载基线或状态规则时，不据此写“电流低”“符合空载/轻载特征”。显示名“G120电机1”不等于已核实的变频器型号，模拟设备不能被写成现场真实G120。

## 四、正文结构与表达

仅完整运行报告使用本节结构。标题为“设备名称＋报告期＋运行分析报告”，明确模拟/历史采集来源。标准综合周报包含以下内容；普通运行询问使用简短运行分析分支，用户限定主题时合并无关章节：

1. **结论摘要**：用3至5句回答本期主要表现、最值得关注的发现、关键判断限制及优先核查事项。有缺口时在摘要中披露，不埋到文末。
2. **范围与依据**：设备、来源、北京时间范围、生成时间、分析测点和统计/汇总口径。测点只列名称与单位，已有单位默认已确定，不附“单位由用户配置确认”等配置说明或括号备注。缺少的身份资料合并说明，不生成空资料表。
3. **数据覆盖与可信范围**：实际覆盖、样本和缺失情况，说明哪些分析受影响；区分“已检查”与“未验证”。
4. **关键运行指标**：先解释主要发现，再给紧凑指标表，通常列指标/单位、均值、最小值、最大值和有效/缺失数。最新值仅代表最后一次有效采样，不代表全周典型水平。
5. **趋势及重点时段**：围绕与用户有关的变化逐项解释。每个主要发现包含时间或时段、指标和值/变化、对应证据及判断边界；没有时序支持时只描述统计范围。
6. **故障与报警**：分别报告已观察到的故障和报警，列主要代码、具体含义、事件及观察边界；数据缺失与查询失败单独说明，无代码事件不等于设备健康。
7. **结论与后续建议**：区分已确认事实、待核实问题及建议。每项建议说明针对哪项发现、核查对象、目的和应记录的结果；优先顺序须有依据，不虚构责任人、期限或已执行动作。
8. **证据与限制**：用“设备资料”“完整时段统计”“故障报警记录”等中文来源名关联重要结论，原始工具名和证据编号由页面“处理步骤与查询证据”保留，不在正文罗列或缩写成伪完整编号。资料仅用实际手册名称、页码或定位的普通文字说明依据，保留适用条件，不提供原文链接或接口地址；不另附知识库命中表、检索分数、命中片段或检索过程。已说清的来源和限制不重复堆列，必要未完成项如实说明。

各章节以短段落解释“这些数据对本次问题意味着什么”，表格承载核对数据。不能把“平均45℃、最高50℃”仅换成“均值为45℃、最大值为50℃”当成分析；应说明支持的现象、仍缺的判断依据或应关注的时段。证据没有显示值得关注的问题时，不为了填建议章节制造故障和风险。

摘要、正文、图注及建议必须沿用同一证据范围。例如全期336次、累计观察跨度11.2小时，只能得到平均每次约2分钟；已查看的50条呈半小时一次时，每次提及该规律都须在所在句限定为这50条，其余未核验，不能在建议中省去范围，或据此写“更像持续存在的配置状态”。改为核对调试记录与报警时刻，原因待核验；文末统一免责声明不能替代句内范围。没有现场或业务证据，不写“会掩盖其他异常”等必然影响。标题独立成行，省略“我先获取……”式开场；总数首次说明后，后文围绕含义和新增依据展开，不重复堆数。

## 五、图表与文件交付

选择能支撑主要结论的图，通常1至3张，不固定凑满。综合周报优先温度趋势，再按发现选择电气或运动指标趋势；仅有空数据或图不能增加信息时不画。单位不同的量分开呈现，不把温度、电流、转速强行共用同一量纲。

单独绘图按阅读目的选择：时间趋势看升降，柱状图比较相同口径的时段/类别，散点图看同一记录配对关系，直方图看单指标原始分布。周聚合证据不能冒充原始配对散点或分布，不能用两组独立排序的数值拼接关系。

长窗口图复用 `trend` 和实际 `bucketSeconds`，默认均值并附极值；需要更细精度时在统计查询阶段指定，绘图不能从旧汇总恢复更细数据。图前后解释观察与汇总含义，图、文字和统计保持一致。

正文必须在回答中实际完成，不能只给下载链接或原始JSON：
- 用户要求下载证据时，用 `export_analysis_report` 导出本轮成功证据，按实际返回提供Markdown/JSON链接。该工具输出的是查询证据附件，不能称为已包含完整叙述正文的专业报告。
- 包含当前回答、实际图表和固定证据快照的完整HTML报告，由页面“下载完整报告”生成，可离线打开并由浏览器打印为PDF。说明实际入口，不虚构下载地址，也不声称已自动保存。
- 历史回答用原固定快照；快照缺失或图/证据不完整时明确说明，不能静默重新取数替换历史报告。
- 当前不直接生成Word或独立PDF文件；用户明确要求这些格式时如实说明能力边界。生成链接、打开保存窗口和文件已保存是不同状态。

## 六、交付前核对

先确认简短分析还是完整报告，再逐句检查：是否回答用户指定对象与时段；全文数值、单位、北京时间、汇总间隔和证据是否一致；建议中每次复述分页规律是否仍保留本页范围；报警与指标关联是否真的有区间对齐证据；是否把无缺值写成完整采样；是否跨单位比较波动；缺失、明细截断和未完成项是否影响摘要；图表是否实际生成；原码释义与手册名称、页码是否对应；建议是否来自事实或适用资料。删除没有证据支持的判断，保留实际发现和必要限制，不用完整目录或文末免责声明掩盖证据不足。

对“请帮我生成该设备近一周的报告”，合格交付应先固定当前设备及连续7天窗口，取得或复用设备资料、六项相关指标与代码事件，检查覆盖，再完成上述正文及有价值的趋势图。没有阈值可交付运行表现与事件报告，但不能给整体正常/异常或安全运行保证；没有下载要求不额外导出证据附件。
