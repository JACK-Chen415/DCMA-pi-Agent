# 可视化与报告

## 先确定用户要看清什么、带走什么

“画图”需要先明确图要回答的问题；“报告”需要区分已有结果整理与新增分析。对象、时段和指标从当前问题或已有分析继承，只澄清会影响呈现含义的缺项。

| 阅读目的 | 合适的交付 | 需先检查的证据 |
| --- | --- | --- |
| 看何时升降、异常前后变化 | 时间趋势 | 对应窗口的时序采样，保留缺失与真实时间间隔 |
| 比较设备、时段或类别 | 可比的趋势或柱状比较 | 相同口径、单位和实际覆盖，避免用最新值替代窗口指标 |
| 看两个指标是否一起变化 | 散点关系 | 同一记录配对的两个指标，不能将两组独立排序数值拼成配对 |
| 看数值集中在哪里 | 分布图 | 单个指标的有效样本及分组口径 |
| 分享或复核已有分析 | 回答、图表和证据组成的报告 | 结果是否完整、可定位，是否仍可读取相应快照 |

用户已指定图型时尊重选择；如果它无法表达所需结论，说明具体限制并采用可行呈现，不擅自增加一套新分析。

## 根据证据状态执行

- 本轮已有足够证据：直接生成图或证据报告，复用相同范围。
- 缺少数据或计算：只补所需部分，交给运行分析或故障排查 Skill；不得让模型补采样值。
- 要整理历史回答：使用页面保留的固定快照和“下载完整报告”。历史证据编号不能作为本轮工具输入；需要重新分析时明确这是对原时段的新查询，不能静默替换旧结果。
- 快照缺失、图与统计范围不一致：指出缺项，不宣称完整交付。仅当用户明确接受文字摘要时，交付有说明的摘要。

绘图和导出参数由现有工具定义约束。模型可调用的证据报告是Markdown／JSON；独立HTML完整报告由页面生成，可离线查看和打印。用户要求Word或独立PDF时说明当前能力，不承诺已生成。

## 完成标准

图表应实际生成，且能回答阅读目的；图、文字和统计的来源、窗口、指标及聚合含义一致。报告应包含用户所需内容、必要限制和真实可用的结果入口。生成链接、打开保存窗口与文件实际保存是不同状态，按实际成功状态说明交付。
