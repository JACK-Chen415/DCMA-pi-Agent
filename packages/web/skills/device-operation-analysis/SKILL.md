# 设备运行分析

## 先确定用户要的结论

结合当前问题、已选设备和有效上下文，确定对象、指标、时段及用户想解决的问题。简单读数直接处理；复杂任务在内部明确预期交付，不向用户展示思考过程或固定问卷。基础数据规则和工具参数沿用系统提示词与工具定义。

| 用户意图 | 所需结果 | 执行分支 |
| --- | --- | --- |
| 了解现在的读数 | 数值、单位、采集时间 | 取最新采样；不因此追加历史诊断 |
| 了解一段时间如何变化 | 范围、变化方向及相关数据特征 | 对该窗口做统计，按问题解释变化；用户需要看变化形态时组合绘图 |
| 统计超过条件的采样 | 条件命中的点数及有效样本数 | 用窗口统计的条件计数；无需连续事件规则 |
| 统计发生了几次、持续多久 | 事件次数、观察区间及未观察到的边界 | 先区分代码事件与连续超限事件，再确定对应的事件规则 |
| 比较设备或时段 | 同口径差异及可比范围 | 对齐测点、时段和单位；区分最新值比较与窗口均值比较 |
| 判断是否正常或是否超限 | 对明确规则的判断 | 查已有规则；缺判断依据时交付可确认的事实，指出尚不能完成的判断 |

“几次”“是否异常”等表达不直接等于某一种计算。只在上下文不能消除且会改变结果时澄清；用户明确要“超过50℃的采样点数”时，不再追问事件间隔。查询失败或没有样本是取证结果，不解释成0次异常。

## 从结论反推最少证据

根据分支选最新采样、窗口统计、比较或事件能力，不先固定读取目录和全部指标。只有结果可信度受采样问题影响时再补质量检查。已经明确的条件直接使用；对“基本信息”的默认范围遵循现有产品约定，不另设默认时段。

若用户问原因，先交付已确认的数据现象，再组合 `fault-investigation`；问图或报告时，将同一分析结果交给 `analysis-visualization-report`。组合任务共用对象与固定窗口，不重复执行相同分析。

## 交付前核对

回答必须解决所选分支的问题：读数有采集时间，统计有计数对象和范围，比较有共同口径，规则判断有依据。数据未覆盖请求范围或关键条件不足时，明确已完成部分和剩余缺口；不把“取到了数据”当成“完成了分析”。
