# 设备运行分析

## 先确定用户要的结论

结合当前问题、已选设备和有效上下文，确定对象、指标、时段及用户想解决的问题。简单读数直接处理；复杂任务在内部明确预期交付，不向用户展示思考过程或固定问卷。基础数据规则和工具参数沿用系统提示词与工具定义。

取得工业数据后通过 `submit_analysis` 交付。用结论类型选择本轮证据：指标范围用metric_summary，汇总趋势用trend，条件点数用condition_count，代码事件用events，本页规律用event_pattern并传原码，阈值用threshold，连续性用continuity，窗口比较用comparison，状态用state，近期或原始记录预览用reading；手册解释用manual。数值和正文由程序生成，不填写自由结论。默认brief；明确要报告再用report。没有比较口径及计算结果的“最平稳”、没有基线的“偏小”、未对齐的报警影响，均不能通过交付校验。图表先完成再交付，失败最多修正一次。

| 用户意图 | 所需结果 | 执行分支 |
| --- | --- | --- |
| 了解现在的读数 | 数值、单位、采集时间 | 取最新采样；不因此追加历史诊断 |
| 泛问一段时间运行得怎么样 | 主要表现、关键数据、故障报警及必要限制 | 查询完整时段后简短分析，不自动生成完整报告目录 |
| 了解一段时间如何变化 | 范围、变化方向及相关数据特征 | 对该窗口做统计，按问题解释变化；用户需要看变化形态时组合绘图 |
| 统计超过条件的采样 | 条件命中的点数及有效样本数 | 用窗口统计的条件计数；无需连续事件规则 |
| 统计发生了几次、持续多久 | 事件次数、观察区间及未观察到的边界 | 先区分代码事件与连续超限事件，再确定对应的事件规则 |
| 比较设备或时段 | 同口径差异及可比范围 | 对齐测点、时段和单位；区分最新值比较与窗口均值比较 |
| 判断是否正常或是否超限 | 对明确规则的判断 | 查已有规则；缺判断依据时交付可确认的事实，指出尚不能完成的判断 |

“几次”“是否异常”等表达不直接等于某一种计算。只在上下文不能消除且会改变结果时澄清；用户明确要“超过50℃的采样点数”时，不再追问事件间隔。查询失败或没有样本是取证结果，不解释成0次异常。

## 从结论反推最少证据

根据分支选最新采样、窗口统计、比较或事件能力，不先固定读取目录和全部指标。只有结果可信度受采样问题影响时，按系统提示词的条件补质量检查。已经明确的条件直接使用。

用户指定一天或一周时，直接对完整时段调用窗口统计；后端自动聚合，不因原始明细上限擅自改为最近几小时或让用户拆分。分桶曲线用于趋势，完整窗口统计用于结论，不将桶均值简单平均。需要逐点连续性的事件或分布分析仍须取得原始证据，不能拿聚合值替代。

若用户问原因，先交付已确认的数据现象，再组合 `fault-investigation`；问图或报告时，将同一分析结果交给 `analysis-visualization-report`。组合任务共用对象与固定窗口，不重复执行相同分析。

“帮我看看这台电机最近一周运行得怎么样”属于普通运行分析。取证可复用报告Skill的范围、指标与事件流程，交付先用二至四个短段落回答主要表现、值得关注的事件及尚不能判断的事项；按价值补关键指标表或趋势图，不套正式报告标题及八节目录。用户明确要求报告、日报、周报或详细展开时，再使用完整报告结构；不因要简短而缩小查询窗口或省掉故障报警核对。

## 设备基本信息的默认范围

默认交付设备资料和最近一小时概况；用户指定其他时段时遵循指定范围，明确只要静态资料时不查采样。

- 用 `get_device_profile` 读取名称、厂家、型号、安装位置和投运日期，仅展示已有资料；缺项合并成一句，不生成空资料表，不主动罗列单位配置、额定值或状态规则。
- 按本轮当前时刻固定同一个一小时窗口，用 `summarize_metrics` 查询电机温度 `motor_temp`、直流母线电压 `dc_voltage`、电流 `current_actual`、转速 `speed_actual`，用 `get_code_events` 查询同一窗口的故障和报警事件。不另查目录、近期100条快照或综合证据包。
- 先简述该时段的主要发现，再展示北京时间范围、采样数量、最后采样时间、四项指标的最新有效值和最小/最大值，以及已观察到的故障/报警事件次数。缺失、状态判断及原码释义遵循系统提示词，不把缺记录当0次，不把未结束事件当当前故障。
- 不为概况编造或追问最大采样间隔、过期阈值，不自动画图或导出报告。

## 交付前核对

回答必须解决所选分支的问题：读数有采集时间，统计有计数对象和范围，比较有共同口径，规则判断有依据。数据未覆盖请求范围或关键条件不足时，明确已完成部分和剩余缺口；不把“取到了数据”当成“完成了分析”。

逐句检查结论和建议：分页规律每次都限定为本次已查看的事件；无报警区间对齐证据不判断报警时指标表现；无连续性检查不把完整时段查询或无缺值写成完整采样。建议说明要核对的记录或对象，不将待确认原因改写成事实。
