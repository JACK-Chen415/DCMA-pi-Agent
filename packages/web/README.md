# DCMA 工业数据分析工作台

React 前端和本地 Node HTTP 服务通过同一个地址运行。Pi SDK 只在服务器端读取本机授权信息，浏览器不会获得密钥。默认只监听 `127.0.0.1`。

## 启动

项目根目录：

```bash
npm install --ignore-scripts
npm run web:dev
```

打开 http://127.0.0.1:3000/ 。`DCMA_PORT` 可以覆盖端口。Ctrl+C 同时停止页面服务与正在执行的模型请求。

### 聊天页与展板统一运行

先在仓库根目录执行 `npm --prefix dashboard ci --ignore-scripts` 安装展板锁文件中的依赖。随后只需 `npm run web:dev`，聊天页位于 `/`，展板位于 `/dashboard/`，无需另外启动3001端口的数据库服务。两套页面保留各自目录和样式，共用展板数据库后端、连接池及只读查询规则，统一读取 `dcma` 数据。

聊天页默认使用数据库数据，每3秒检查一次；设备列表对应四个模拟来源和一个历史真实采集来源，名称来自数据库记录。右侧四项指标为电机温度、直流电压、实际电流和实际转速；未提供的类型、位置、投运日期显示“未提供”，不根据原始状态码猜测运行状态。原设备示意图保留。切换来源会清空旧来源显示，失败时明确提示，不用示例值代替；同一来源刷新失败可保留上次成功结果。

“查看更多”在当前标签页进入 `/dashboard/?table=当前来源#realtime`，展板直接选择同一电机及模拟/历史真实来源。浏览器返回恢复聊天页及已保存会话。导入数据仍为显式离线模式，可以“返回数据库数据”；展板始终读取 MySQL，不展示导入文件。

Agent 请求携带当前来源，`read_industrial_dashboard` 工具复用展板近期采样查询；原表目录和筛选工具保留。该工具返回最新记录及以列名、行数组表示的最近窗口，最多100条原始记录中的有效时间采样，截断会标记；时间按展板暂定北京时间解释，结果不能代替全库统计。

“设备信息查询”默认同时回答设备资料和最近一小时概况：采样数量、最后采样时间、电机温度/直流电压/实际电流/实际转速的最新有效值及范围，以及该窗口已观察到的故障报警事件次数。统计与代码事件复用同一完整窗口，不用近期100条快照代替一小时结果。不把无故障报警解释为运行正常；缺少状态规则时明确运行状态尚无法确认。用户明确只查静态资料时不查询采样，指定其他时段时使用指定范围。

### 工业分析工具与后台监测

网页 Agent harness 显式注册17项工具，包括数据库目录/当前采样/原始记录、设备资料、数据质量、时间窗口统计、窗口比较、连续超限、代码事件、规则状态判断、故障码查询、维护知识检索、诊断证据、报告、证据绘图以及告警/任务管理。名称、全部参数及逐项使用案例见 [工具说明](tools/README.md)；`GET /api/tools` 可查看实际注册的参数 Schema，无需模型授权或数据库连接。

统计在受限只读事务取回的完整窗口上由程序计算：每次最多7天、20000行/16MiB，超限拒绝而不返回部分统计。每轮最多16次工具调用、8次数据读取、4个不同分析窗口；单次结果最多62000字节。设备资料、字段单位、状态规则和厂家知识需人工提供，缺失时保持未知。配置格式见 [配置说明](tools/config/README.md)。工具已接入不代表真实故障诊断效果已验收。

配置、报告、监测任务和本机告警均位于已忽略的 `packages/web/.dcma-runtime/`，不会进入浏览器存储或Git。报告下载仅接受程序生成的编号。创建、修改、暂停或恢复后台任务时，Agent 只返回待确认链接，由用户在本机页面核对后执行；不会自动创建任务。已确认活动任务在后端运行期间执行，服务重启后恢复；只保存本机告警，不控制设备或发送外部通知。

### 工业 Skill

网页 Agent 在服务启动时通过 Pi 的 `loadSkillsFromDir` 发现本项目 `skills/` 下四份版本化 Skill：

| Skill | 使用范围 |
| --- | --- |
| `device-operation-analysis` | 区分了解现状、量化变化、统计点数／事件、比较及规则判断 |
| `fault-investigation` | 区分代码释义、实际异常排查和下一步检查，围绕候选原因取证 |
| `analysis-visualization-report` | 按阅读目的呈现趋势、差异、关系或分布，区分已有结果整理与新分析 |
| `work-order-draft` | 区分整理、修改与提交意图，交付可审核的对象、证据、动作和复核缺口 |

2026-10-23更新至1.1.0：先明确用户要的交付结果，再确定证据与必要分支，最后核对完成标准；只澄清会改变结果的关键缺项。组合任务共享已有条件与证据，不因涉及多个Skill而重复查询。通用数据规则和工具参数仍由系统提示词与工具定义维护，Skill聚焦任务决策。此次未改为按需加载，仍使用下述服务端预加载方式。

网页没有文件读取工具，Pi默认不会展示可按需读取的Skill列表。因此服务端将这四份简短正文预加载到系统提示词，模型按description采用相关流程，用户不需要输入命令。仅填写`getSkills`列表无法实现此效果。既有17项业务工具和系统规则保留，不开放任意文件读取，不加载个人或其他项目Skill。修改Skill后需重启后端；旧回答不会重写。工单Skill只输出草稿，不代表工单系统已接入。

离线验证：`node --import ./packages/coding-agent/src/experimental/source-resolver.ts --test packages/web/test/skills.test.ts`（仓库根目录）。验证发现、版本与实际SDK请求上下文，不调用真实模型或数据库；实际模型选用流程的效果仍需固定问题回归。

1.1.0真实模型页面验收共5组请求，2项通过、3项部分通过；趋势判断、假设来源与阈值口径仍需改进。详细场景、验收记录和截图保存在个人仓库。

### 导入本地知识文档

在仓库根目录执行以下命令，Python 环境需有 `pypdf==6.10.0`（可使用 Codex 随附的 Python 环境）：

```bash
python scripts/import-knowledge.py --source ../knowledge
```

导入来源为 `S120_故障手册.pdf`、两份电机说明书（90L-4、YFB801-2）及对应的对拖试验故障模拟实施方案，共四个文件。脚本在本地提取 PDF 和 DOCX 文本，按故障定义或章节生成 `packages/web/.dcma-runtime/knowledge.json`，校验完成后原子替换旧索引；不会修改原件、调用模型或联网。资料更新后重新执行即可，工具每次查询都会重新读取索引。

故障手册按厂家“西门子”、型号“SINAMICS S120/S150”、版本“06/2020”保存，保留 PDF 页码、原书页码、跨页处理说明以及同一码不同驱动对象的定义。F/A 代码分别用于故障/报警精确查询，包括标题中显式列出的可配置 F/A 类型，结果仍保留原始标题和条件；N/C 通知及安全信息也可全文检索，不添加手册未声明的代码类型。只有代码而不知道手册身份时，Agent 先检索原码，从结果取得身份后精确查询，并引用原文出处。手册身份代表资料范围，不代表现场设备已核实适用。

两份电机说明书按章节检索；试验方案标为场景资料 `case`，不当作厂家故障码结论。资料仅作为检索证据，不会执行其中的操作说明。数据库表与两台电机的对应关系尚未由资料明确，因此导入不会自动生成 `profiles.json`、设备告警阈值或状态规则。文档和生成索引均留在本机，不随代码提交。

电机1～4已确认为模拟设备，可在仓库根目录执行 `node scripts/configure-simulation-profiles.ts` 初始化本机 `profiles.json`。该命令只配置四个模拟来源的名称和展板已有的18项测点单位，保留真实厂家、型号、版本、额定值和运行规则未知，不套用两台真实电机的参数。已有配置文件时会拒绝覆盖，避免丢失人工设置；历史真实采集表不在本命令的初始化范围内。

设备资料工具另返回 DCMA 采样约定：故障/报警码0表示该次采样未报告故障/报警，非零需查手册，缺失不能当0；该约定不用于推断 `status`、控制字、状态字、运行状态或设备健康。没有阈值时，Agent 仍可结合数据特征检索已导入资料，引用来源给出参考排查建议；只有超限判定需要另行明确模拟阈值。

回答或报告展示具体故障码、报警码时，默认同时提供原码和具体含义；非零码主动检索手册，多个码逐项对应并保留出处。参考手册适用性未确认时注明，查不到可靠释义时写“含义未确认”，不猜测。零码分别写明“该次采样未报告故障／报警”，缺失不能当作零码。此规则用于后续生成，不改写已保存的旧回答。

离线验证导入解析与知识服务：

```bash
python scripts/test_import_knowledge.py
node --test packages/web/test/knowledge.test.ts
```

生产预览前需分别执行 `npm run web:build` 和 `npm --prefix dashboard run build`，生成两套静态资源。两套页面在生产模式下仍由同一服务提供；开发验证不代表生产构建已验证。

首次克隆缺少 Pi 模型数据文件时，执行 `npm run hydrate:model-data`。

## 可用功能

### 语音、处理步骤、证据与完整报告

统一服务支持 Windows、macOS 和 Linux 导出，适用于完整HTML报告、回答文字、会话记录、图表PNG／SVG／CSV、聊天中的证据报告链接及展板趋势图片。

- 后端在 Windows 上运行时，保留本机原生“另存为”窗口，由用户选择文件夹和文件名。首次从 D 盘打开，同一次服务运行中记住上次选择的文件夹；不允许保存到 C 盘。取消时不写文件，成功后显示实际保存路径；覆盖同名文件需要在窗口中确认，写入失败时保留原文件。
- 后端在 macOS 或 Linux 上运行时，使用浏览器标准下载，无需 PowerShell 或额外桌面对话框程序。保存位置和是否询问位置由浏览器设置决定；界面显示“已交由浏览器下载”，不声称已写入确定磁盘路径。浏览器取消或拦截下载时，可在其下载记录中查看和重试。

两种路径均先经本机导出接口验证普通建议文件名、匹配的文件类型、非空内容及32MiB上限。浏览器下载保留原始文件字节，不在后端写入副本；Windows实际路径只来自本机选择窗口。单独启动旧展板服务时不提供该接口，需使用统一工作台服务导出。

- 输入框提供中文语音识别，识别文字先填入输入框，可编辑后手动发送；不自动提交。麦克风权限由浏览器管理，拒绝权限、网络失败或不支持时有明确提示，仍可键盘输入。浏览器语音服务可能联网，页面在输入框下提示。
- 点击语音按钮后先检查音频输入访问并立即释放检查用音轨，再启动识别；区分权限拒绝、无输入设备、设备占用和浏览器识别服务失败。取消或离开页面后不会在延迟授权成功时自动启动识别，失败也不会锁住文字输入。内置浏览器可能提供识别接口却无法采集音频，此时可在Chrome打开同一页面，或聚焦输入框按Windows的Win+H；实际识别效果仍需在目标浏览器确认。
- 完成回答后可手动朗读、停止朗读；开始新的朗读或语音输入会停止旧朗读。使用浏览器语音能力，不新增模型凭据或语音SDK；浏览器支持、语音服务网络与实际麦克风效果需在目标设备确认。
- 生成时显示当前查询、统计、资料检索或绘图步骤及等待时间。步骤和成功证据引用随会话保存，刷新后随同一个生成任务恢复。工具执行预算不再包含模型等待；连续120秒无进展或总执行5分钟会中止并保留部分结果，原模型超时的现场原因仍需真实请求时序验证。
- “处理步骤与查询证据”可查看来源、北京时间范围、样本数量、统计、阈值点数、资料出处和原文，并展开精确查询条件及完整结果。证据是本机固定快照，重启后可读，旧会话不自动补查。
- “下载完整报告”生成独立HTML文件，包含问题、Markdown排版的回答、内嵌SVG图表、完整图表数据及查询／资料证据，离线打开无需本机服务；可通过浏览器打印保存PDF。图表使用完整快照视野，缺失或归档的快照会阻止伪完整导出。
- “下载回答文字”继续提供纯Markdown；Agent已有的Markdown／JSON证据报告工具及图表PNG／SVG／CSV下载保持独立。完整HTML不自动合并同一会话的其他轮次。
- `summarize_metrics`支持严格大于或小于阈值的采样点计数，区分等于阈值、未命中和缺失；只查点数时不要求连续事件规则。


- 新建、切换、重命名、删除和导出真实会话；会话、图表引用及上次打开的位置保存在本机后端，配置和导入数据保存在当前浏览器；Agent 图表数据快照保存在本机私有运行目录。
- 设备按数据库来源选择；原始状态码尚未解码，显示“状态未确认”。显式导入模式可按设置阈值标记温度超限。
- CSV / JSONL / LOG 文件导入，逐行验证时间和数值；真实 CSV 下载和 Markdown 分析报告下载。
- 数据库侧栏显示电机温度、电压、电流、转速近期趋势；原离线遥测图表和频谱计算模块保留。
- 响应式布局，小屏可通过顶部按钮打开会话与设备面板；弹窗支持 Escape 和键盘焦点。
- 仅提供 Agent 对话，支持 Pi SDK 流式回复、停止生成和错误显示。每次调用带入最近 20 条有效消息；关闭数据库优先查询时，提供当前数据集最新最多200个原始采样点，分析由模型完成。

## 数据导入

CSV 示例（时间必须包含日期，推荐 ISO 8601 并带时区）：

```csv
timestamp,temperature,vibration,current,speed
2026-10-08T00:00:00Z,46.8,0.32,312,1498
2026-10-08T00:00:01Z,50.2,0.34,313,1497
```

时间为必填列，至少提供一个指标。单位分别是 ℃、mm/s、A、rpm。支持中文列名“时间”“温度”“振动”“电流”“转速”。LOG / JSONL 每行一个对应字段的 JSON 对象。上限 2 MB、10000 行；重复时间、非法数值与不匹配列数会拒绝导入。

空通道显示“—”。设备看板和图表使用原始时间间隔；温度警戒阈值用于看板预警。Agent 接收到的有限数据窗口不能用于推断全量数据的统计或设备健康分数。

## 使用真实模型

DeepSeek 官方接口已配置在 `models.json`：`https://api.deepseek.com`，模型 `deepseek-flash`（DeepSeek V4.1 Flash）。复制 `.env.example` 为本目录的 `.env` 并填写 `DEEPSEEK_API_KEY`，然后重启服务。`.env` 已被 Git 忽略，勿将密钥写入前端或提交到仓库。服务器只读取本项目的模型配置；Pi 的现有授权仍可使用。

网页设置选择“DeepSeek V4.1 Flash”，保存后回复由真实模型生成。本工作台每次回复最多输出 4096 token；费用估算使用官方高峰价格，实际扣费以提供商账单为准。

在项目根目录运行 `./pi-test.sh`，通过 `/login` 完成 Pi 模型授权，或者在启动服务的终端配置对应提供商的环境变量。授权后在网页设置中刷新模型列表，选择实际模型，保存并应用。

模型调用使用所选提供商，可能消耗其额度。现有功能默认启用，无需选择工具；数据库优先查询设置仅决定默认数据来源，不撤销数据库工具的调用权限。网页模型会话没有执行终端命令或修改文件的工具。

`GET /api/health` 返回后端状态与已授权模型元数据。`POST /api/chat` 携带与助手消息ID一致的UUID `requestId`，返回 NDJSON 流，事件包含 `snapshot`、`delta`、`chart`、工具进度、`done`、`cancelled` 或 `error`；需要同源请求、JSON 内容类型及 `X-DCMA-Client: web` 请求头。`GET /api/chat/{requestId}` 先返回完整文字和图表快照，再继续同一任务的流；`DELETE /api/chat/{requestId}` 明确停止生成，需要 `X-DCMA-Client: web`。

## 工业 MySQL 数据库

在本目录的 `.env` 配置 `MYSQL_HOST`、`MYSQL_PORT`、`MYSQL_USER`、`MYSQL_PASSWORD`；默认端口为3306，可用 `MYSQL_DATABASE` 限制到指定库。凭据只由 Node 后端读取，不进入浏览器或 Git。需要本机能访问学校内网数据库；在家可能需要学校 VPN。

网页设置中的“工业 MySQL 数据库”，点击“检查连接与表结构”读取实际目录，再点击表名预览20行。`GET /api/database/catalog` 返回连接状态、实际列名和类型；`GET /api/database/rows?schema=...&table=...&limit=20` 读取表数据。共用展板接口的已知表白名单；展板及 Agent 当前设备工具固定读取 `dcma`。

Agent 默认优先 MySQL；显式导入模式下可以在设置中关闭数据库优先，以分析离线文件。17项工具始终注册，未配置数据库时查询明确失败，知识和告警工具仍可使用。当前设备读数优先使用同源展板工具，需要额外筛选时查询实际字段。所有工业数据库查询运行在只读事务中，不能执行任意 SQL、写入或删除。原始记录最多200行，近期采样最多100条原始记录中的有效时间点；分析工具的范围及预算见上文。原预览 SQL 超时5秒，分析 SQL 超时10秒，工具等待和事务支持取消。返回记录只代表声明的窗口，不代表全库统计。

- `real_data_01`、`real_data_02`、`real_data_03`、`real_data_04`：实时模拟数据。
- `real_data`：短暂真实采集的数据。

MySQL 未连通时，网页和 Agent 明确报告未取得数据。侧栏已经与展板的字段和数据来源对应，不用示例代替查询结果；导入文件属于独立离线数据。单位与时间解释沿用展板现有口径，设备位置、类型、投运日期及状态码定义仍需外部台账或手册确认。数据库接口和页面读取可验证，不等于模型诊断效果已完成验收。

## 当前边界

原示例台账和采样生成模块保留，但不再驱动当前设备侧栏，也不用于数据库失败回退；设备图片仍为示意图。导入文件属于离线数据，当前没有直接传感器采集。厂家故障解释来自本地导入手册，回答保留资料型号、版本、出处和适用条件，通用建议不会被标成已确认根因。

聊天最多保留 50 个会话、每个会话 200 条消息，文件总大小上限32MiB。会话保存在 `packages/web/.dcma-runtime/conversations/state.json`，采用临时文件写入、同步到磁盘后原子替换；该目录已被 Git 忽略。三名开发者分别在自己电脑启动服务时，各自保存记录，无需登录，也不会通过拉取或合并代码共享聊天。重新打开页面或重启后端后会恢复上次会话；清除浏览器站点数据不影响已保存到后端的聊天，但会清除浏览器中的配置和导入数据。

首次启用且后端尚无会话文件时，自动迁移当前浏览器的历史记录。已有后端记录后，以后端为准，不用旧浏览器列表重新添加已删除会话。发起模型调用前先保存用户消息和助手消息ID；回复结束和会话操作及时保存，连续生成期间每秒保存一次；关闭页面时另尝试保存并保留浏览器待同步副本。刷新或关闭页面只断开浏览器订阅，后端仍继续生成；重新打开后自动连接原任务，恢复已有文字、图表和后续输出，不重复调用模型。停止生成按钮会明确取消任务，现有120秒超时仍有效。后端内存保留活动任务和最近100轮已完成回复；重启后端会停止在途任务，刷新时保留已保存内容并提示重新发送，不自动重跑。关闭浏览器或电脑突然断电仍可能丢失尚未写入的最后部分内容。

读取失败会阻止自动覆盖并提供重试、导出浏览器记录入口；保存失败会提示且保留当前页面内容。多个页面同时修改时，旧版本会被拒绝，请先导出当前记录再刷新。`GET /api/conversations` 读取记录，`PUT /api/conversations` 校验版本后保存，需要同源请求、JSON 内容类型及 `X-DCMA-Client: web` 请求头。离线回归测试：`node --test packages/web/test/conversations.test.ts packages/web/test/chart-message.test.ts packages/web/test/chat-runs.test.ts`，不调用模型或工业数据库。Agent 对话需要有效模型授权；模型不可用时明确提示，不生成本地模板回复。
