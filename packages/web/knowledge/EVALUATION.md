# 工业知识检索小样本评测

在仓库根目录运行：

```sh
node packages/web/knowledge/evaluate.ts
node --env-file-if-exists=packages/web/.env packages/web/knowledge/evaluate.ts --hybrid
```

第一条命令只跑关键词基线。第二条用相同问句对比基线与当前配置下的真实混合检索，最多发出 5 次查询嵌入调用，服务自身的有界重试另计。无需启动网页、查询数据库或调用聊天模型。嵌入服务与索引按 [接入说明](EMBEDDING.md) 配置。缺少配置、索引校验未通过或查询降级时，评测会报告原因并返回非零退出码。首个查询降级后跳过后续查询，以免重复访问不可用服务。

八个固定问句及人工标注在 [evaluation-cases.ts](evaluation-cases.ts)。查询直接进入生产检索函数，保留原始中文问句，不附加事先标注的来源或故障码。PDF 页码从仓库内 PDF 文件第一页算起，DOCX 以索引的段落定位为准。

- **精确查码**比较代码、手册来源、页码和上下文完整性。两题的正确条目均应排第 1。带码查询按现有设计跳过嵌入，两种配置下都可以检查这一点。
- **自然语言现象**比较相关故障条目或指定手册段落的排名。只有实际使用了查询向量的结果进入混合汇总，`keyword-paired` 使用同一组问句作为对照。
- **适用性**单独记录已标记为不适用的来源是否进入前 3 条。G120 案例的语料没有可适用的厂家定义，只有另一个接线案例有预期命中，因此命中率以 `withApplicableEvidence` 为分母。该指标只衡量本组查询中指定的错误来源进入检索结果的风险。

使用实际 Qwen3-Embedding-8B 和匹配的 856 条、4096 维索引。5 条无代码查询得到真实混合结果，3 条带码查询保持精确检索。

混合检索唯一新增命中为对拖通讯丢包，试验方案段落 54–61 位列第 3。明确指定 G120 的 F30004 查询仍把 S120 手册第 380–381 页排在第 1。90L-4 接线题两路的前 3 条均未出现不适用的 YFB801-2 手册，也未召回 90L-4 的接线段落。这些数字仅描述固定问句的检索表现，评测范围限于检索结果。

## 2026-11-20 检索排序改进后复测

针对首跑暴露的问题改进了 `knowledge-index.ts` 的词法评分：CJK 查询切 2-gram 并按 IDF 加权；口语说法（嗡嗡响、转得慢、时有时无等）扩展为手册用语（通电不启动、转速不足、数据丢包）；查询点名的设备型号对归属记录加权；查询点名 G120 而非 S120 时，S120 手册整体移出候选并记入 `retrieval_log.family_conflict`；docx 首段元数据概览按导航内容降权。语料与向量索引未变。
